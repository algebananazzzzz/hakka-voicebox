# 客家话音库 (Hakka Voicebox) design

## Purpose

杨老师 records Hakka pronunciations of everyday words and sentences so the family can hear and keep the language. Family members open the site on any device, read each entry in Chinese, English and Hakka romanisation, and play his real recording. He manages the library from a recording studio page: add and edit entries, record audio, record a greeting, and set the homepage photo and text.

Success means: a recording saved on his device plays for every family member on every device, he never sees a technical concept beyond one password, and the site costs nothing to run.

## Source design

Claude Design project `4d0c4398-bf9c-4aa2-a663-8436aa00ba8c`: `home.dc.html`, `public.dc.html`, `manage.dc.html`, `store.js`. The prototype stores everything in the visitor's browser (IndexedDB and localStorage), so nothing is shared between devices. This project keeps its visual design and interaction flow and replaces the storage layer with a shared backend.

The prototype files are downloaded to `design-handoff/` (gitignored) for visual-parity comparison.

## Architecture

Everything runs on Cloudflare. No database, no other cloud, no credentials beyond one password.

```
hakka.algebananazzzzz.com
  Worker prd-web-worker-hakkavb
    /*                Astro static build, served as Workers static assets
    /api/*            Hono API in the same Worker
    /media/*          audio and photo objects streamed from R2

  R2 bucket prd-db-bucket-hakkavb  (bound to the Worker, not public)
    library.json                    settings, categories, entries
    history/<ulid>.json             snapshot written on every save
    audio/<entryId>/<ulid>.<ext>    entry recordings
    greeting/<ulid>.<ext>           homepage greeting
    photo/<ulid>.jpg                homepage portrait
```

Names follow `{env}-{zone}-{resource}-{project_code}` with `env = prd` and `project_code = hakkavb`. There is one environment.

The Worker owns the bucket through a binding, so it reads and writes R2 without access keys. Static asset requests never run Worker code and are not metered. `run_worker_first` sends only `/api/*` and `/media/*` to the Worker.

## Data model

`library.json` holds the whole library. A few hundred entries is about 50 KB.

```ts
type Kind = 'word' | 'sentence';

interface Entry {
  id: string;          // ULID, generated by the server
  order: number;       // display order, ascending
  category: string;    // must be present in Library.categories
  kind: Kind;
  zh: string;          // required, non-empty
  en: string;
  py: string;          // Mandarin pinyin
  rom: string;         // Hakka romanisation
  audioKey: string | null;
}

interface Settings {
  name: string;        // e.g. 杨老师; the seal shows its first character
  intro: string;
  note: string;
  portraitKey: string | null;
  greetingKey: string | null;
}

interface Library {
  version: 1;
  settings: Settings;
  categories: string[]; // display order
  entries: Entry[];
}
```

These types live in one module imported by both the Worker and the pages.

Only Hakka audio is stored. The prototype's word list plays English and Mandarin through the browser's speech synthesis and nothing records them, so `store.js`'s `en`/`zh` audio slots are dropped.

Category rename and delete exist in `store.js` but no page calls them, so they are not built. A new category is created by saving an entry with a category name not yet in the list; the server appends it.

### Starter library

When `library.json` does not exist, the API serves a starter library bundled in the Worker: the 61 entries and 6 categories from `store.js` (`招呼语, 屋家人, 数目, 食物饮料, 动作与形容, 日常`), with settings `name: 杨老师` and the prototype's default intro and note. The first save writes it to R2. There is no separate seed step.

The prototype defaults to `杨景友` on the homepage and `杨老师` elsewhere. The real site uses the single `settings.name`, editable from the studio.

### Concurrent edits

Every write is a read-modify-write of `library.json` guarded by R2's conditional put: read the object and its etag, apply the change, `put` with `onlyIf: { etagMatches }`. The very first save, when no object exists yet, uses R2's create-only condition (`If-None-Match: *`); if R2 turns out not to support that, the first save is unconditional, which can race only on the site's first-ever edit. On a precondition failure the Worker re-reads and reapplies, up to 3 attempts, then returns 409. R2 is strongly consistent, so a read after a successful save always sees it.

After each successful save the Worker also writes the same JSON to `history/<ulid>.json`. Recordings are never overwritten (every upload gets a new key), so the history snapshots are enough to recover from a bad edit.

### Media writes

For an upload the Worker writes the new object first, then saves `library.json` pointing at it, then deletes the previous object. A failure between steps leaves at most one orphaned object, never a dangling reference. Deleting an entry removes it from `library.json` first, then deletes its audio object.

## API

All responses are JSON except `/media/*`. Errors are `{ "error": string }` with status 400 (validation), 401 (password), 404 (unknown entry or media), 409 (save conflict after retries) or 413 (body too large).

| Method | Path | Auth | Body | Result |
|---|---|---|---|---|
| GET | `/api/library` | no | | `Library`, `Cache-Control: no-store` |
| POST | `/api/auth/check` | yes | | 204 |
| POST | `/api/entries` | yes | entry fields without `id`, `order`, `audioKey` | created `Entry`, appended at the end |
| PUT | `/api/entries/:id` | yes | entry fields without `id`, `order`, `audioKey` | updated `Entry` |
| DELETE | `/api/entries/:id` | yes | | 204 |
| PUT | `/api/entries/:id/audio` | yes | raw audio | updated `Entry` |
| PUT | `/api/settings` | yes | `{ name, intro, note }` | `Settings` |
| PUT | `/api/settings/greeting` | yes | raw audio | `Settings` |
| PUT | `/api/settings/portrait` | yes | raw image | `Settings` |
| GET | `/media/:key+` | no | | object bytes, `Cache-Control: public, max-age=31536000, immutable` |

Audio accepts `audio/webm`, `audio/ogg` and `audio/mp4` (Safari's MediaRecorder output), capped at 8 MB. The object extension follows the content type. Images accept `image/jpeg`, capped at 2 MB; the browser crops and re-encodes before upload. `/media/*` serves only keys under `audio/`, `greeting/` and `photo/`, so `library.json` and `history/` are never exposed there.

### Password

The password is a Worker secret `MANAGE_PASSWORD`, set from the GitHub secret of the same name. Writes send `Authorization: Bearer <password>`; the Worker compares in constant time. Reads are public.

`/manage` first shows a password field and calls `/api/auth/check`. On 204 it keeps the password in localStorage, so he enters it once per device. Any 401 later clears it and shows the field again.

## Frontend

Astro 7 static output with React 18 islands, Tailwind v4 and strict TypeScript, matching algebananazzzzz.com. Colours come from the prototype palette as CSS tokens. Fonts load from Google Fonts (EB Garamond, Noto Sans SC, Noto Serif SC, Ma Shan Zheng): Google serves CJK fonts in unicode-range slices, which self-hosted CJK packages do not.

| Route | Prototype | Island |
|---|---|---|
| `/` | `home.dc.html` | portrait, greeting playback, intro, recorded-count stat, note |
| `/words` | `public.dc.html` | tabs, category chips, search, grouped cards, per-viewer text size and speech speed |
| `/manage` | `manage.dc.html` | password gate, greeting, photo and text, progress, entry list, record modal, add/edit modal |

`public.dc.html` is renamed `/words` because the whole site is public. `/manage` stays unlinked from the other pages, as in the prototype, and carries `noindex`.

All islands load data through one `api.ts` client and one `useLibrary` hook. Media URLs are `/media/<key>`. Filtering, grouping, sorting (unrecorded first in the studio) and counts stay client-side as in the prototype, in pure functions under `src/lib/`.

The prototype's `image-slot` only persists inside Claude Design. The studio instead takes a click or drag-and-drop file, crops the centre square to 800×800 on a canvas, encodes JPEG, and uploads it.

Per-viewer text size and speech speed stay in localStorage (`hvb-settings`), as in the prototype.

## Deployment

`wrangler.jsonc` declares the Worker, the static assets directory, the R2 binding and the custom domain `hakka.algebananazzzzz.com`. There is no Terraform: the only resource outside the Worker is the bucket, and CI creates it when `wrangler r2 bucket info prd-db-bucket-hakkavb` reports it missing.

- `1-feature-branch-ci.yml`, on pull requests to `main`: format check, `astro check`, Worker type check, Vitest (frontend and Worker), build.
- `2-prd-deploy.yml`, on push to `main`: the same checks, ensure the bucket exists, `astro build`, `wrangler secret put MANAGE_PASSWORD`, `wrangler deploy`.

GitHub secrets: `CLOUDFLARE_API_TOKEN` (Workers scripts, R2, Workers routes and DNS on the zone), `CLOUDFLARE_ACCOUNT_ID`, `MANAGE_PASSWORD`.

## Testing

- Worker: Vitest with `@cloudflare/vitest-pool-workers`, running the Hono app against a local R2. Covers starter library on first read, create/edit/delete, new category appended on save, 401 without or with a wrong password, conditional-put retry on a concurrent change, upload type and size rejection, old object deleted after replacement, audio deleted with its entry, `/media` refusing `library.json` and `history/`.
- Frontend: Vitest for the filter, grouping, sorting and count functions and the API client's error handling.
- Visual parity: Playwright screenshots of `/`, `/words` and `/manage` beside the prototype pages served from `design-handoff/`.

## Out of scope

Recording English or Mandarin audio, renaming or deleting categories, reordering entries, multiple user accounts, and a preprod environment.
